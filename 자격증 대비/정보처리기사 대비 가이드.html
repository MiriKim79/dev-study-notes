0. 시작 전에 — 자주 나오는 용어#

용어쉬운 설명
NCS (국가직무능력표준)실무에서 필요한 능력을 국가가 표준화해 정리한 기준. 정보처리기사 실기 문제의 근거가 됨
요구사항 분석시스템이 무엇을 해야 하는지 정리하는 단계. 이 사이트의 팀 개발 시작 가이드 3장과 같은 개념
화면 설계사용자가 보는 화면의 배치와 흐름을 정리하는 단계
정규화데이터 중복을 없애도록 테이블을 분리하는 설계 원칙(SQLD 대비 가이드 2장 참고)
프로세스(Process)실행 중인 프로그램 하나. 운영체제가 CPU·메모리를 배분하는 단위
스레드(Thread)프로세스 안에서 실제로 작업을 수행하는 흐름 단위
관계대수(Relational Algebra)릴레이션(테이블)에 대한 연산을 수학적으로 표현하는 방법
소프트웨어 생명주기(SDLC)요구사항 분석부터 설계·구현·테스트·유지보수까지 소프트웨어가 만들어지고 관리되는 전체 과정
결합도(Coupling)모듈 간에 서로 얼마나 의존하는지 나타내는 정도. 낮을수록 좋은 설계
응집도(Cohesion)한 모듈 안의 기능들이 얼마나 밀접하게 관련되는지 나타내는 정도. 높을수록 좋은 설계
이상현상(Anomaly)정규화가 안 된 테이블에서 데이터를 조작할 때 생기는 삽입·갱신·삭제 문제
OSI 7계층네트워크 통신을 7단계로 나눠 표준화한 모델
CIA(정보보안 3요소)기밀성·무결성·가용성 — 정보보안이 지켜야 할 세 가지 목표

1. 시험 구성#

정보처리기사는 필기와 실기 두 단계로 나뉩니다.

필기 — 5과목#

과목다루는 내용이 사이트와 연결
소프트웨어 설계요구사항 분석, UML, 화면 설계, 아키텍처 패턴팀 개발 시작 가이드 3~6장
소프트웨어 개발자료구조, 테스트, 통합·배포테스트 자동화 중급 가이드
데이터베이스 구축데이터 모델링, 정규화, SQL, 트랜잭션SQLD 대비 가이드, 데이터베이스 중급 가이드
프로그래밍 언어 활용변수·제어문 등 프로그래밍 공통 개념, 운영체제 기초, 네트워크 기초프론트·백엔드 기초 가이드
정보시스템 구축관리소프트웨어 공학, 보안, 프로젝트 관리보안 심화 가이드, 팀 협업 중급 가이드

필기는 객관식이며, 과목별 최소 점수와 전체 평균 최소 점수를 모두 넘겨야 합격입니다.

실기#

필답형(서술형+단답형) 통합 실기시험으로, NCS 기반 실무 시나리오 문제가 나옵니다. 100점 만점에 일정 점수 이상이면 합격입니다(정확한 기준은 공식 공고 확인).

기본 상식: 필기는 "얼마나 많이 아는가"를, 실기는 "실무 상황에서 그 지식을 적용할 수 있는가"를 봅니다. 필기 합격 후 일정 기간 안에 실기에 합격해야 최종 자격을 취득합니다.

2. 과목별 핵심 포인트#

소프트웨어 설계#

text
요구사항 분석 → 정적/동적 요구사항으로 구분
UML 다이어그램 → 클래스 다이어그램(구조), 시퀀스 다이어그램(흐름) 등 종류별 용도 구분
아키텍처 패턴 → MVC, 계층형 아키텍처 등의 개념과 장단점

결합도와 응집도 — 좋은 설계를 판단하는 기준#

개념좋은 방향의미
결합도(Coupling)낮을수록 좋음모듈 간에 얼마나 서로 의존하는가
응집도(Cohesion)높을수록 좋음한 모듈 안의 기능들이 얼마나 밀접하게 관련되는가

기본 상식: "결합도는 낮게, 응집도는 높게"가 좋은 설계의 기본 원칙입니다. 결합도가 높으면 한 모듈을 고칠 때 다른 모듈까지 영향을 받고, 응집도가 낮으면 한 모듈 안에 관련 없는 기능이 뒤섞여 유지보수가 어려워집니다. 시험에서는 결합도 종류(자료 결합도 < ... < 내용 결합도)나 응집도 종류를 순서대로 묻는 문제가 나옵니다.

소프트웨어 개발#

text
자료구조: 배열, 연결 리스트, 스택, 큐, 트리 — 각각의 특징과 시간복잡도
테스트: 화이트박스(내부 로직 기준) vs 블랙박스(입출력 기준) 테스트 구분

정렬 알고리즘 개요#

알고리즘방식평균 시간복잡도
버블 정렬인접한 두 값을 계속 비교·교환O(n²)
선택 정렬매번 최솟값을 찾아 앞으로 보냄O(n²)
삽입 정렬이미 정렬된 부분에 값을 하나씩 끼워 넣음O(n²)
퀵 정렬기준값(pivot) 기준으로 나눠서 재귀적으로 정렬O(n log n)

시험에서는 정렬 알고리즘 코드를 주고 "이건 무슨 정렬인가", "n개일 때 비교 횟수는 몇 번인가"를 묻는 유형이 나옵니다.

데이터베이스 구축#

SQLD 대비 가이드에서 다룬 정규화·SQL 기본 문법과 범위가 많이 겹칩니다. 여기에 더해 트랜잭션의 4가지 특성(ACID)이 자주 나옵니다.

특성의미
원자성(Atomicity)트랜잭션은 전부 실행되거나 전혀 실행되지 않아야 함
일관성(Consistency)트랜잭션 전후로 데이터베이스는 항상 일관된 상태여야 함
고립성(Isolation)동시에 실행되는 트랜잭션들이 서로 영향을 주지 않아야 함
지속성(Durability)커밋된 결과는 시스템 장애가 나도 유지되어야 함

이상현상(Anomaly)과 정규화#

정규화가 안 된 테이블에서 데이터를 조작할 때 생기는 세 가지 문제입니다.

text
삽입 이상: 학생을 등록하려는데 아직 배정된 반이 없어 반 정보를 억지로 NULL로 넣어야 함
갱신 이상: 같은 정보가 여러 행에 중복 저장돼있어, 하나만 수정하면 나머지와 값이 달라짐
삭제 이상: 한 행을 지웠더니 그 안에 같이 있던 다른 필요한 정보까지 함께 사라짐

정규화는 바로 이 세 가지 이상현상을 없애기 위한 과정입니다(SQLD 대비 가이드 2장의 정규화 단계와 이어집니다).

프로그래밍 언어 활용#

C/Java/Python 등 여러 언어의 기본 문법(반복문, 조건문, 배열)을 언어 상관없이 읽고 결과를 계산하는 문제가 나옵니다. 특정 언어를 깊이 아는 것보다, 여러 언어의 공통 문법 패턴을 읽어내는 연습이 중요합니다.

OSI 7계층 — 네트워크 기초#

계층이름예시
7응용 계층HTTP, FTP
6표현 계층데이터 형식 변환, 암호화
5세션 계층연결 세션 관리
4전송 계층TCP, UDP
3네트워크 계층IP, 라우팅
2데이터링크 계층MAC 주소, 이더넷
1물리 계층케이블, 전기 신호

기본 상식: 아래에서 위로 "물-데-네-전-세-표-응"(물리→데이터링크→네트워크→전송→세션→표현→응용)으로 외우는 것이 흔한 암기법입니다. 시험에서는 각 계층의 대표 프로토콜이나 장비(라우터=3계층, 스위치=2계층)를 매칭하는 문제가 나옵니다.

정보시스템 구축관리#

text
보안: 대칭키/비대칭키 암호화 개념, 접근 통제 모델(보안 심화 가이드와 연결)
프로젝트 관리: WBS(작업 분해 구조), 일정 관리 기법(간트차트 등)

정보보안의 3요소(CIA)#

요소의미
기밀성(Confidentiality)인가된 사람만 정보에 접근할 수 있어야 함
무결성(Integrity)정보가 허가 없이 변경되지 않아야 함
가용성(Availability)필요할 때 정상적으로 서비스를 이용할 수 있어야 함

소프트웨어 개발 방법론#

방법론특징
폭포수 모델(Waterfall)요구사항→설계→구현→테스트를 순서대로 한 번에 진행. 계획이 명확할 때 적합
애자일(Agile)짧은 주기로 개발·검토를 반복. 요구사항이 자주 바뀔 때 적합(팀 협업 중급 가이드 참고)
나선형 모델(Spiral)폭포수+반복 개발에 위험 분석을 추가해 점진적으로 완성해나감

3. 연습문제#

⚠️ 아래 문제는 개념 이해를 돕기 위해 직접 만든 연습문제이며, 실제 정보처리기사 기출문제가 아닙니다.

문제 1. 트랜잭션의 ACID 특성 중, "동시에 실행되는 트랜잭션이 서로 영향을 주지 않아야 한다"는 특성은? A) 원자성(Atomicity) B) 일관성(Consistency) C) 고립성(Isolation) D) 지속성(Durability)

Q1. 트랜잭션의 ACID 특성 중, 트랜잭션이 완료되면 그 결과가 영구적으로 반영되어야 한다는 특성은? A) 원자성(Atomicity) B) 일관성(Consistency) C) 고립성(Isolation) D) 지속성(Durability)

정답 보기

정답: D

지속성(Durability)은 커밋된 트랜잭션의 결과가 시스템 장애가 발생해도 영구적으로 보존되어야 한다는 특성입니다.

Q2. 결합도(Coupling)와 응집도(Cohesion)에 대한 설계 원칙으로 옳은 것은? A) 결합도는 높게, 응집도는 낮게 B) 결합도는 낮게, 응집도는 낮게 C) 결합도는 낮게, 응집도는 높게 D) 결합도는 높게, 응집도는 높게

정답 보기

정답: C

좋은 모듈 설계는 모듈 간 의존성(결합도)은 낮추고, 모듈 내부 요소 간 관련성(응집도)은 높이는 것을 목표로 합니다.

Q3. OSI 7계층 중 IP 주소를 이용한 라우팅을 담당하는 계층은? A) 물리 계층 B) 데이터링크 계층 C) 네트워크 계층 D) 전송 계층

정답 보기

정답: C

네트워크 계층(3계층)은 IP 주소 기반 경로 설정(라우팅)을 담당합니다. 전송 계층(4계층)은 TCP/UDP로 종단 간 신뢰성 있는 전달을 담당합니다.

Q4. 프로그램 내부의 코드 구조(제어 흐름)를 보고 테스트 케이스를 설계하는 방식은? A) 블랙박스 테스트 B) 화이트박스 테스트 C) 인수 테스트 D) 회귀 테스트

정답: B

화이트박스 테스트는 내부 로직·구조를 알고 있는 상태에서 구문 커버리지, 분기 커버리지 등을 기준으로 테스트 케이스를 설계합니다.

Q5. 관계형 데이터베이스에서 후보키 중 기본키로 선택되지 않은 나머지 키를 무엇이라 하는가? A) 외래키(Foreign Key) B) 대체키(Alternate Key) C) 슈퍼키(Super Key) D) 복합키(Composite Key)

정답: B

후보키 여러 개 중 기본키로 선정된 것을 제외한 나머지를 대체키라고 부릅니다.

Q6. 소프트웨어 개발 생명주기(SDLC) 모델 중, 폭포수 모델의 가장 큰 한계로 지적되는 것은? A) 각 단계 반복이 잦아 일정 예측이 어렵다 B) 이전 단계로 돌아가기 어려워 요구사항 변경에 유연하게 대응하기 힘들다 C) 문서화를 전혀 하지 않는다 D) 소규모 프로젝트에만 적용 가능하다

정답: B

폭포수(Waterfall) 모델은 단계를 순차적으로 진행하는 것을 전제로 해 이전 단계로 되돌아가는 비용이 크고, 요구사항 변경에 취약합니다.

Q7. IPv4와 비교했을 때 IPv6의 특징으로 옳은 것은? A) 주소 길이가 32비트로 더 짧다 B) 주소 공간이 128비트로 훨씬 넓다 C) 헤더 구조가 더 복잡해 라우팅이 느리다 D) 보안 기능(IPsec)을 지원하지 않는다

정답: B

IPv6는 128비트 주소 체계를 사용해 IPv4(32비트)보다 훨씬 넓은 주소 공간을 제공하며, IPsec을 기본 지원합니다.

5. 합격 꿀팁#

  • 한 과목도 포기하지 마세요. 5과목 전부 과락 없이 넘겨야 하므로, 잘하는 과목만 파고 약한 과목을 방치하면 총점이 높아도 떨어집니다.
  • 필기는 범위를 순서대로 정독하기보다, 최근 몇 회차 기출을 반복해서 푸는 것이 훨씬 효율적입니다. 기출 변형 문제가 많이 나옵니다.
  • 필기 합격에는 유효기간이 있습니다. 실기 응시 기한을 캘린더에 미리 표시해두세요.
  • 실기는 서술형입니다. 개념을 눈으로 읽기만 하지 말고, "이걸 다른 사람에게 말로 설명한다면" 이라는 마음으로 직접 써보는 연습을 미리 해두세요.

6. 자주 하는 실수#

  • 필기 5과목을 각각 따로 공부하고, 서로 겹치는 부분(DB·보안 등)을 놓침
  • ACID 각 특성의 정의를 예시 없이 단어만 외움
  • 필기 합격 후 실기 응시 기한을 놓쳐 필기를 다시 봐야 하는 상황이 됨
  • 실기를 필기처럼 암기 위주로만 준비해 서술형 문제에서 감점

7. 실전 체크리스트#

  • 5과목의 범위를 이 사이트의 다른 가이드와 연결해서 이해했는가
  • 결합도·응집도의 의미와 좋은 방향을 아는가
  • 트랜잭션 ACID 4가지를 예시와 함께 설명할 수 있는가
  • 삽입·갱신·삭제 이상현상을 예시로 설명할 수 있는가
  • 화이트박스/블랙박스 테스트 차이를 아는가
  • OSI 7계층을 순서대로 나열하고 대표 프로토콜을 매칭할 수 있는가
  • 정보보안 3요소(기밀성/무결성/가용성)를 아는가
  • 응시 자격과 필기·실기 접수 일정을 공식 사이트에서 확인했는가
  • 실기가 서술형이라는 점을 감안해 개념을 "말로 설명하는" 연습을 했는가

헷갈리는 짝구분
폭포수 모델 vs 애자일 모델폭포수는 단계를 순차적으로 한 번씩 진행(요구사항 변경에 취약), 애자일은 짧은 주기로 반복하며 점진적으로 개발
결합도 vs 응집도결합도는 모듈 간 의존 정도(낮을수록 좋음), 응집도는 모듈 내부 요소들이 얼마나 관련 있는지(높을수록 좋음)
화이트박스 vs 블랙박스 테스트화이트박스는 내부 코드 구조 기반(구문·분기 커버리지), 블랙박스는 입출력 명세 기반(동등분할, 경계값분석)
TCP vs UDPTCP는 연결 지향·신뢰성 보장(느림), UDP는 비연결·신뢰성 미보장(빠름, 실시간 스트리밍 등에 사용)
프로세스 vs 스레드프로세스는 독립된 메모리 공간을 가진 실행 단위, 스레드는 프로세스 내에서 메모리를 공유하며 실행되는 더 가벼운 단위
정규화 vs 반정규화정규화는 중복 제거로 데이터 일관성 확보, 반정규화(역정규화)는 조회 성능을 위해 의도적으로 중복 허용

11. 시험 직전 최종 점검 리스트#

  • 소프트웨어 개발 방법론(폭포수/애자일/나선형)의 특징과 차이를 설명할 수 있는가
  • 결합도는 낮게, 응집도는 높게 설계해야 하는 이유를 설명할 수 있는가
  • SQL DDL/DML 기본 구문(CREATE, INSERT, SELECT, UPDATE)을 직접 작성할 수 있는가
  • 정규화 이상현상(삽입/갱신/삭제)을 실제 테이블 예시로 설명할 수 있는가
  • OSI 7계층과 TCP/IP 4계층을 매칭하고 각 계층의 대표 프로토콜을 아는가
  • 실기 서술형 대비: 핵심 용어를 정의만이 아니라 예시를 들어 설명하는 연습을 했는가

12. 계산·트레이스 문제 심화 풀이#

이 장은 필기·실기에서 반복적으로 나오는 "계산해서 답을 구하는" 유형을 단계별 풀이 과정과 함께 정리합니다. 아래 문제는 모두 개념 이해를 위한 오리지널 창작 예제입니다.

12.1 결합도 판별 문제#

결합도는 약한 것(좋음)부터 강한 것(나쁨) 순서로 다음과 같이 나뉩니다.

순서(약함→강함)결합도 종류특징
1자료 결합도(Data Coupling)필요한 값만 매개변수로 주고받음
2스탬프 결합도(Stamp Coupling)필요 없는 필드까지 포함된 구조체·객체 전체를 넘김
3제어 결합도(Control Coupling)상대 모듈의 내부 동작을 제어하는 플래그(flag) 값을 넘김
4외부 결합도(External Coupling)외부에 선언된 변수(전역이 아닌 외부 참조)를 공유
5공통(공유) 결합도(Common Coupling)전역 변수를 여러 모듈이 함께 사용
6내용 결합도(Content Coupling)다른 모듈 내부 로직·데이터를 직접 참조/변경

예제 문제: 아래 세 가지 코드 조각을 결합도가 약한 순서대로 나열하라.

text
① calc_tax(price)                     // 세금 계산에 필요한 값 price만 전달
② calc_tax(order)                     // order 객체 전체(고객명·주소·상품목록 등)를 통째로 전달, 실제로는 price 필드만 사용
③ calc_tax(mode)                      // mode 값이 1이면 부가세, 2이면 특별소비세 계산 로직으로 분기하도록 지시

풀이 과정

  1. ①은 계산에 필요한 값 하나만 넘기므로 자료 결합도.
  2. ②는 필요 이상의 구조(객체 전체)를 넘기므로 스탬프 결합도.
  3. ③은 상대 모듈의 "실행 로직 자체"를 결정하는 제어 플래그를 넘기므로 제어 결합도.
  4. 약한 순서: 자료(①) < 스탬프(②) < 제어(③)

정답: ① → ② → ③

12.2 응집도 판별 문제#

응집도는 강한 것(좋음)부터 약한 것(나쁨) 순서로 다음과 같이 나뉩니다.

순서(강함→약함)응집도 종류특징
1기능적 응집도(Functional)모듈 내 모든 요소가 단 하나의 기능 수행에 집중
2순차적 응집도(Sequential)한 요소의 출력이 다음 요소의 입력으로 이어지는 흐름
3교환(통신)적 응집도(Communicational)같은 입력 데이터를 사용하지만 서로 다른 기능 수행
4절차적 응집도(Procedural)순서는 있지만 데이터 흐름 관계는 약함(그냥 순서대로 실행)
5시간적 응집도(Temporal)특정 시점(초기화, 종료 등)에 실행되어야 한다는 이유만으로 묶임
6논리적 응집도(Logical)유사한 성격의 기능을 모아두지만 실제로는 관련 없는 로직들이 한 모듈에 섞임
7우연적 응집도(Coincidental)아무 관련 없는 코드가 우연히 한 모듈에 모임

예제 문제: 모듈 system_init()이 "로그 파일 초기화, DB 커넥션 풀 생성, 캐시 워밍업"을 프로그램 시작 시점에 함께 실행한다면 어떤 응집도인가?

풀이 과정: 세 작업은 서로 데이터를 주고받지 않고 논리적으로도 다른 일을 한다. 공통점은 오직 "프로그램 시작 시점에 실행된다"는 시간적 조건뿐이다 → 시간적 응집도.

12.3 진법 변환 문제#

예제 문제: 10진수 173을 2진수와 16진수로 각각 변환하라.

풀이 과정 (2진수)

text
173 ÷ 2 = 86 … 나머지 1
86  ÷ 2 = 43 … 나머지 0
43  ÷ 2 = 21 … 나머지 1
21  ÷ 2 = 10 … 나머지 1
10  ÷ 2 = 5  … 나머지 0
5   ÷ 2 = 2  … 나머지 1
2   ÷ 2 = 1  … 나머지 0
1   ÷ 2 = 0  … 나머지 1
나머지를 아래→위(역순)로 읽으면: 10101101

풀이 과정 (16진수)

text
173 = 128 + 45 = 10×16 + 13
10진수 10 → 16진수 A, 10진수 13 → 16진수 D
따라서 173(10) = AD(16)

검산: AD(16) = A×16 + D = 10×16 + 13 = 160 + 13 = 173 ✅

정답: 173(10) = 10101101(2) = AD(16)

12.4 자료구조 알고리즘 트레이스#

(1) 스택을 이용한 후위표기식 계산#

중위식 (3 + 4) * 5를 후위표기식으로 바꾸면 3 4 + 5 *입니다. 스택으로 이 후위식을 계산하는 과정을 추적합니다.

입력 토큰동작스택 상태(top이 오른쪽)
3push(3)[3]
4push(4)[3, 4]
+pop 4, pop 3 → 3+4=7 → push(7)[7]
5push(5)[7, 5]
*pop 5, pop 7 → 7*5=35 → push(35)[35]

정답: 최종 결과는 스택에 남은 35.

(2) 큐를 이용한 프로세스 스케줄링(FIFO) 트레이스#

도착 순서대로 A, B, C 프로세스가 큐에 들어온다고 할 때 FIFO(선입선출) 방식의 실행 순서는 큐에 들어온 순서와 동일합니다: A → B → C. 큐는 enqueue(뒤에 삽입)와 dequeue(앞에서 제거)만 허용하므로 나중에 온 C가 먼저 실행될 수 없습니다.

(3) 이진 트리 순회(Traversal) 트레이스#

아래와 같은 이진 트리가 있다고 가정합니다.

text
        A
       / \
      B   C
     / \
    D   E
순회 방식순서 규칙결과
전위(Preorder)루트 → 왼쪽 → 오른쪽A, B, D, E, C
중위(Inorder)왼쪽 → 루트 → 오른쪽D, B, E, A, C
후위(Postorder)왼쪽 → 오른쪽 → 루트D, E, B, C, A

풀이 팁: 전위는 항상 루트가 맨 앞, 후위는 항상 루트가 맨 뒤, 중위는 루트가 왼쪽 서브트리와 오른쪽 서브트리 "사이"에 옵니다.

12.5 SQL 실행 결과 예측#

다음 주문 테이블이 있다고 가정합니다.

주문번호고객명금액
1김철수10000
2이영희25000
3김철수15000
4박민수NULL

예제 문제: 아래 SQL의 실행 결과는?

sql
SELECT 고객명, SUM(금액) AS 총액
FROM 주문
GROUP BY 고객명
HAVING SUM(금액) >= 15000;

풀이 과정

  1. GROUP BY 고객명으로 묶으면: 김철수(10000+15000=25000), 이영희(25000), 박민수(NULL, SUM 결과도 NULL)
  2. HAVING SUM(금액) >= 15000 조건 적용: 김철수(25000, 통과), 이영희(25000, 통과), 박민수(NULL >= 15000은 참이 아니므로 제외)

정답:

고객명총액
김철수25000
이영희25000

주의: NULL은 어떤 비교 연산과도 참(TRUE)이 되지 않으므로 HAVING, WHERE 조건에서 자동으로 제외됩니다. SUM/AVG 등 집계 함수는 NULL을 무시하고 계산합니다.

12.6 네트워크 서브넷 계산#

예제 문제: 192.168.1.0/26 네트워크가 있을 때, 사용 가능한 호스트 수와 브로드캐스트 주소를 구하라.

풀이 과정

  1. /26은 서브넷 마스크가 255.255.255.192라는 뜻 (앞 26비트가 네트워크 부분).
  2. 호스트에 사용 가능한 비트 수: 32 − 26 = 6비트
  3. 전체 주소 개수: 2⁶ = 64개
  4. 이 중 네트워크 주소(첫 번째)와 브로드캐스트 주소(마지막)는 호스트에 할당할 수 없음 → 사용 가능한 호스트 수 = 64 − 2 = 62개
  5. 네트워크 주소: 192.168.1.0, 브로드캐스트 주소: 192.168.1.0 + 63 = 192.168.1.63

정답: 사용 가능한 호스트 62개, 브로드캐스트 주소 192.168.1.63

12.7 계산 문제 실전 연습 (정답 클릭 확인)#

Q1. 모듈 A가 모듈 B를 호출하면서, 처리 방식을 지시하는 코드(flag) 값을 매개변수로 전달한다면 이는 어떤 결합도인가?

정답 보기

정답: 제어 결합도(Control Coupling)

상대 모듈의 내부 실행 흐름(분기)을 제어하는 플래그 값을 넘기는 것이 제어 결합도의 전형적인 예입니다.

Q2. 10진수 202를 16진수로 변환하면?

정답 보기

정답: CA(16)

202 = 12×16 + 10. 12는 16진수로 C, 10은 16진수로 A이므로 CA(16)입니다. 검산: C×16+A = 12×16+10 = 192+10 = 202.

Q3. 후위표기식 6 2 3 + - 4 * 를 스택으로 계산한 최종 결과는?

정답 보기

정답: 4

순서대로 push(6), push(2), push(3) → 스택 [6,2,3]. '+' 만나면 pop 3, pop 2 → 2+3=5 → push(5) → [6,5]. '-' 만나면 pop 5, pop 6 → 6-5=1 → push(1) → [1]. push(4) → [1,4]. '*' 만나면 pop 4, pop 1 → 1×4=4 → push(4) → [4]. 최종 결과 4.

Q4. /28 서브넷에서 사용 가능한 호스트 수는?

정답 보기

정답: 14개

호스트 비트 수 = 32-28 = 4비트. 전체 주소 수 = 2⁴ = 16개. 네트워크 주소와 브로드캐스트 주소를 제외하면 16-2 = 14개.

Q5. 이진 트리 A(B(D,E), C)를 후위(Postorder) 순회한 결과는?

정답 보기

정답: D, E, B, C, A

후위 순회는 왼쪽 서브트리 → 오른쪽 서브트리 → 루트 순서입니다. B의 왼쪽(D)·오른쪽(E)을 먼저 방문한 뒤 B, 그 다음 C, 마지막에 루트 A를 방문합니다.

Q6. WHERE 금액 = NULL 조건을 사용한 SQL 쿼리의 결과 행 수는? (금액이 NULL인 행이 존재해도)

정답 보기

정답: 0행 (항상 결과 없음)

NULL은 "값이 없음"을 의미하므로 `=` 비교 자체가 성립하지 않습니다(TRUE도 FALSE도 아닌 UNKNOWN). NULL 여부를 확인하려면 `WHERE 금액 IS NULL`을 사용해야 합니다.
