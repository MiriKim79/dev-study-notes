> **대상:** ChatGPT·Claude·Cursor 같은 AI에게 코드를 맡겨서 빠르게 뭔가 만들어보고 싶은 사람
> **목적:** "바이브 코딩"이 정확히 뭔지, 언제 써도 되고 언제 위험한지 감 잡기
> **주의:** 이 문서는 특정 도구 사용법이 아니라 "AI에게 코드를 맡길 때의 태도와 안전장치"를 다룹니다. 유행어라 정의가 아직 유동적이라는 점을 감안하고 읽어주세요.

# 1. 바이브 코딩이란?

**바이브 코딩(Vibe Coding)**은 개발자가 자연어로 "이런 걸 만들어줘"라고 지시하면 AI가 코드를 작성하고, 그 결과를 코드 한 줄 한 줄 다 이해하지 않은 채로 받아들이면서 진행하는 개발 방식을 가리키는 말입니다. 2025년 2월 AI 연구자 안드레 카파시(Andrej Karpathy)가 SNS에 쓴 표현에서 시작해 널리 퍼졌습니다.

기존에도 AI 코드 어시스턴트(자동완성, 코드 생성 제안)는 있었지만, 바이브 코딩의 핵심은 **"작동 원리를 완전히 이해하지 않고도 코드를 계속 진행한다"**는 태도 자체에 있습니다. "느낌(vibe)대로 큰 그림만 던지고, 세부 로직은 AI에게 맡긴다"는 뜻에서 이름이 붙었습니다.

이 문서를 읽기 전에 알아두면 좋은 것: 이 사이트의 **생성형 AI 기능 개발 기초 가이드**는 "AI 기능을 서비스에 정확하게 통합하는 법"을 다루고, 이 문서는 그것과는 결이 다른 "AI에게 코드 작성 자체를 맡기고 작업하는 워크플로우"를 다룹니다. 서로 대체 관계가 아니라 보완 관계입니다.

# 2. 언제 적합한가

* **빠른 프로토타입**: 아이디어가 실제로 동작하는지 며칠 안에 확인하고 싶을 때
* **개인 사이드 프로젝트, 장난감 프로젝트**: 실패해도 손해가 크지 않은 학습·실험용 코드
* **이미 익숙한 영역의 반복 작업**: 내가 결과 코드를 보면 옳고 그름을 바로 판단할 수 있는 영역(예: CRUD API 뼈대, 간단한 UI 컴포넌트)

# 3. 언제 위험한가

* **프로덕션 서비스, 특히 결제·인증·개인정보를 다루는 코드**: 이해하지 못한 채 배포하면 보안 취약점을 그대로 서비스에 실어 보내는 것과 같습니다.
* **팀 프로젝트에서 리뷰 없이 그대로 머지**: 코드 작성자 본인도 설명하지 못하는 코드는 리뷰어도, 미래의 나도 유지보수할 수 없습니다.
* **내가 전혀 모르는 영역**: 결과 코드가 그럴듯해 보여도 틀렸을 때 그걸 알아챌 방법이 없습니다. (생성형 AI 결과물은 비결정적이고 틀릴 수 있다는 원칙은 **생성형 AI 기능 개발 기초 가이드** 1장에서도 강조합니다.)

### 기본 상식

바이브 코딩은 "AI가 다 알아서 하니 개발자는 몰라도 된다"는 뜻이 아닙니다. 오히려 **AI가 낸 결과를 빠르게 검증할 수 있는 능력**이 있어야 안전하게 쓸 수 있는 방식입니다. 이 사이트의 **Git·GitHub 기초 가이드**, **백엔드 기초 가이드** 같은 기본기가 없는 상태로 바이브 코딩만 하면, 문제가 생겼을 때 원인을 찾을 방법이 없습니다.

# 4. 실전에서 안전하게 쓰는 법

1. **작은 단위로 지시하고, 작은 단위로 커밋한다.** 한 번에 "로그인부터 결제까지 다 만들어줘"가 아니라, 기능 하나씩 요청하고 그때그때 결과를 확인합니다.
2. **결과 코드를 최소한 한 번은 읽는다.** 완벽히 이해하지 못해도, "이 함수가 뭘 하려는 건지" 정도는 스스로 설명할 수 있어야 합니다.
3. **테스트로 검증한다.** 코드를 다 이해하지 못하더라도, 테스트가 통과하는지는 확인할 수 있습니다. **테스트 자동화 중급 가이드**의 최소한만이라도 적용하는 걸 권장합니다.
4. **민감한 부분(인증, 결제, 개인정보 처리)은 직접 검토하거나 아예 AI에게 맡기지 않는다.**
5. **버전 관리를 철저히 한다.** AI가 만든 결과가 이상하면 언제든 이전 커밋으로 되돌릴 수 있어야 합니다. **Git·GitHub 진짜 최소 기초**의 커밋·되돌리기만 알아도 훨씬 안전해집니다.

---

# 5. 자주 하는 실수

* AI가 만든 코드를 그대로 복붙해서 어디서 에러가 나는지도 모른 채 다시 AI에게 "고쳐줘"만 반복하는 것 — 원인을 스스로 좁혀보는 습관이 없으면 문제가 점점 커집니다.
* 프로젝트 초반부터 전체 아키텍처를 AI에게 통째로 맡기는 것 — 구조적인 결정(폴더 구조, 데이터 모델)은 사람이 먼저 큰 방향을 잡고, AI에게는 그 안에서의 구현을 맡기는 편이 안전합니다.
* "AI가 짰으니까 맞겠지"라고 생각하고 보안·성능 검토를 생략하는 것.

# 6. 여기까지 이해했다면

- 바이브 코딩이 기존 AI 코드 자동완성과 뭐가 다른지 설명할 수 있다.
- 바이브 코딩을 써도 되는 상황과 피해야 하는 상황을 구분할 수 있다.
- AI가 만든 코드를 안전하게 다루는 최소한의 습관(작은 단위 커밋, 테스트, 리뷰) 한 가지 이상을 말할 수 있다.
