# 1. 프론트엔드란?

프론트엔드는 사용자가 웹 브라우저에서 직접 보고 조작하는 부분을 만드는 영역입니다. 화면을 그리는 것뿐 아니라, 사용자 입력을 받고, 서버에 데이터를 요청하고, 응답을 화면에 반영하고, 로딩·오류·빈 결과를 처리하는 일까지 포함합니다. 프론트엔드는 보통 데이터베이스에 직접 접근하지 않고, 백엔드(서버 쪽 프로그램. 요청을 받아 응답을 돌려줌)를 통해서만 데이터를 주고받습니다.

```
사용자 → 브라우저 → 프론트엔드 → (HTTP 요청) → 백엔드 API → 데이터베이스
```

# 2. 개발 환경 준비하기

- **Node.js**: 원래 브라우저 안에서만 실행되던 JavaScript를 컴퓨터에서 직접 실행할 수 있게 해주는 프로그램. 프론트엔드 개발 도구들이 이 위에서 동작합니다.
- **npm**: Node.js에 딸려오는 패키지 매니저(라이브러리를 설치·관리하는 도구).
- **`package.json`**: 프로젝트 이름, 설치된 패키지 목록, 실행 명령(`scripts`)을 적어두는 설정 파일.
- **Vite**: 개발 서버(코드를 고치면 바로 화면에 반영해주는, 개발할 때만 쓰는 서버)와 빌드 환경을 빠르게 만들어주는 도구. 요즘 React 프로젝트를 새로 시작할 때 가장 많이 씁니다.

React + Vite로 새 프로젝트를 만드는 예시입니다.

```bash
node --version
npm --version

npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
```

이미 만들어진 프로젝트(예: 팀원이 만든 저장소)를 받았다면 새로 만들지 말고 아래처럼 시작합니다.

```bash
npm install
npm run dev
```

`npm run`만 입력하면 `package.json`에 등록된 실행 명령 목록을 볼 수 있습니다. `npm run dev`를 실행했는데 `Missing script: "dev"` 오류가 뜬다면, 터미널 위치가 프로젝트 폴더가 맞는지부터 확인합니다.

### 프로젝트 폴더 구조

기능이 늘어나면 보통 화면 단위(`pages/`), 재사용 부품(`components/`), 서버 요청 함수(`api/`)로 폴더를 나눕니다. **URL 경로 하나에 대응하면 pages, 여러 곳에서 재사용되면 components**입니다. `api/`를 따로 두면 서버 주소나 요청 방식이 바뀔 때 한 곳만 고치면 됩니다. 처음부터 다 만들 필요는 없고 필요해질 때 추가하면 됩니다.

파일을 나누면 `import`/`export`로 연결합니다.

```js
// api.js
export async function getCourses() {
  const response = await fetch("/api/courses");
  return response.json();
}

// CoursePage.jsx
import { getCourses } from "./api";
```

# 3. HTML — 화면의 구조

HTML(HyperText Markup Language)은 웹페이지의 구조와 의미를 작성하는 언어입니다.

```html
<header>
  <h1>온라인 서점</h1>
</header>

<main>
  <article>
    <h2>책 제목</h2>
    <p>책 설명</p>
    <button type="button">장바구니 담기</button>
  </article>
</main>
```

중요한 건 화면 모양이 아니라 **의미에 맞는 태그**를 쓰는 것입니다. 제목은 `h1`~`h6`, 문단은 `p`, 목록은 `ul`/`ol`/`li`, 클릭 동작에는 `div`보다 `button`이나 `a`를 사용합니다. 이미지에는 `alt` 속성을, 입력창에는 `label`을 연결합니다.

# 4. CSS — 화면의 표현

CSS(Cascading Style Sheets)는 배치, 크기, 색상, 간격, 반응형을 담당합니다.

**선택자(Selector)**로 "어떤 엘리먼트(HTML 태그로 만들어진 화면 요소 하나)를 꾸밀지" 지정합니다(`.class`, `#id` 등). 모든 요소는 margin-border-padding-content 순의 **박스 모델(Box Model)**로 크기가 정해지고, 레이아웃은 한 방향 정렬에는 **Flexbox**, 행과 열을 함께 구성할 때는 **Grid**를 씁니다.

CSS는 "나중에 쓴 코드가 무조건 이긴다"가 아니라 **명시도(Specificity, 선택자가 얼마나 구체적인가에 따른 우선순위)**를 함께 봅니다. 스타일이 안 먹으면 `!important`부터 붙이지 말고 **브라우저 개발자 도구 → Elements → Styles/Computed**에서 어떤 규칙이 덮어쓰고 있는지 확인합니다.

# 5. JavaScript — 화면의 동작

JavaScript는 사용자 동작에 반응하고, 데이터를 처리하고, 화면을 바꾸는 역할을 합니다. `const`/`let`으로 **변수**(값을 담는 이름표)를 선언하고, **함수**(동작을 묶어 이름 붙인 코드 덩어리)로 로직을 구성합니다.

자주 쓰는 배열 메서드입니다.

```js
const products = [
  { id: 1, name: "키보드", price: 50000 },
  { id: 2, name: "마우스", price: 30000 },
];

const names = products.map((product) => product.name);
const expensive = products.filter((product) => product.price >= 40000);
```

서버 요청처럼 결과가 바로 오지 않는 작업은 **비동기(Async)**로 처리합니다. `Promise`(비동기 작업의 결과를 나중에 받기로 약속한 객체)를 동기 코드처럼 읽기 쉽게 쓰는 문법이 `async`/`await`입니다.

```js
async function loadProducts() {
  try {
    const response = await fetch("/api/products");
    if (!response.ok) throw new Error("상품을 불러오지 못했습니다.");
    return await response.json();
  } catch (error) {
    console.error(error);
    throw error;
  }
}
```

# 6. 브라우저와 DOM

브라우저는 HTML을 읽어서 JavaScript가 다룰 수 있는 객체 구조로 바꿉니다. 이걸 **DOM(Document Object Model)**이라고 합니다. 클릭, 입력처럼 사용자가 하는 행동을 **이벤트(Event)**라고 하고, "이 이벤트가 발생하면 이 함수를 실행해라"라고 등록하는 것을 **이벤트 리스너(Event Listener)**라고 합니다(React에서는 10장의 `onClick`처럼 더 간단하게 씁니다). React, Vue 같은 프레임워크도 결국은 이 DOM을 효율적으로 갱신해주는 도구입니다.

---

# 7. 클라이언트와 서버

**클라이언트**(사용자의 브라우저)는 화면 표시, 입력 처리, API 요청을 담당합니다. **서버**(원격 컴퓨터에서 실행되는 프로그램)는 데이터 검증, 인증, 데이터베이스 접근, 비즈니스 로직을 담당합니다.

가장 중요한 원칙: **프론트엔드 검증만으로 보안을 보장할 수 없습니다.** 예를 들어 프론트에서 관리자 버튼을 숨겨도, 서버가 권한을 다시 검사해야 진짜로 안전합니다. 프론트엔드 코드와 브라우저 저장소는 사용자가 열어볼 수 있으므로, API Key나 비밀번호를 프론트 코드에 넣지 않아야 합니다.

# 8. HTTP와 API

프론트엔드와 백엔드는 **API**(정해진 형식으로 데이터를 주고받기 위한 약속)를 통해 통신합니다. 이때 쓰는 통신 규약이 HTTP입니다.

**HTTP 메서드**: `GET`(조회), `POST`(생성), `PUT`/`PATCH`(수정), `DELETE`(삭제).

**자주 보는 상태 코드**: `200`(성공), `400`(요청값 오류), `401`(인증 필요), `403`(권한 없음), `404`(주소 없음), `500`(서버 내부 오류).

응답 데이터는 보통 **JSON**(`{ "key": "value" }` 형태의 데이터 형식)으로 옵니다. API를 다룰 때는 성공 응답만 가정하지 말고, 네트워크 요청이 느리거나 실패할 수 있다는 것을 항상 염두에 둬야 합니다. `fetch`/`axios`는 브라우저에서 이런 HTTP 요청을 보낼 때 쓰는 JS 도구입니다.

### CORS — "분명 되는 요청인데 브라우저가 막는" 상황

`localhost:5173`(프론트)과 `localhost:5000`(백엔드)처럼 포트가 다르면 브라우저는 이를 막을 수 있습니다(**CORS** 정책). 이건 프론트 코드가 틀렸다는 뜻이 아니라 브라우저가 적용하는 보안 정책입니다. 자세한 내용은 [프론트엔드 중급 가이드](../개발%20중급%20가이드/프론트엔드%20중급%20가이드.html)를 참고하세요.

# 9. 상태(State)란?

상태는 **화면에 영향을 주며 시간이 지나면서 바뀌는 값**입니다. 로그인 여부, 입력창 값, 장바구니 수량, 서버에서 받은 목록, 로딩 여부 등이 모두 상태입니다. 크게 **지역 상태**(한 컴포넌트 안에서만 쓰는 값), **공유 상태**(여러 화면이 함께 쓰는 값, 예: 로그인 사용자), **서버 상태**(서버에서 가져온 데이터)로 나눠 생각하면 편합니다.

기본 원칙: 모든 값을 전역 상태로 만들지 않는다, 계산으로 얻을 수 있는 값은 따로 저장하지 않는다, 로딩·성공·빈 결과·실패 상태를 구분한다.

# 10. 컴포넌트 기반 개발과 React

React, Vue, Svelte 같은 프레임워크는 모두 화면을 작은 단위인 **컴포넌트**(재사용 가능한 화면 조각. 레고 블록 하나에 비유할 수 있음)로 나눠서 만듭니다. 좋은 컴포넌트는 역할이 명확하고, 입력과 출력이 분명하며, 너무 많은 일을 하지 않습니다.

바닐라 JavaScript로 DOM을 직접 조작해도 화면은 만들 수 있지만, 화면이 복잡해질수록 "어떤 상태가 바뀌면 어떤 부분을 다시 그려야 하는지"를 손으로 다 관리하기 어려워집니다. React 같은 라이브러리는 **"상태가 바뀌면 화면을 자동으로 다시 그린다"**는 규칙 하나로 이 문제를 해결해줍니다. (React는 웹 자체가 아니라 UI를 만드는 라이브러리이고, 이걸 쓰더라도 HTML/CSS/JS 기초는 계속 필요합니다.)

### 실제 코드로 보는 Props와 State

```jsx
// CourseCard.jsx — 부모가 전달한 값(Props)을 받아 화면에 그리기만 하는 컴포넌트
function CourseCard({ title, price }) {   // title, price가 Props: 부모가 넘겨준 읽기 전용 값
  return (
    <div className="course-card">
      <h2>{title}</h2>
      <p>{price === 0 ? "무료" : `${price}원`}</p>
    </div>
  );
}

// CourseList.jsx — 이 컴포넌트 안에서 바뀌는 값(State)을 직접 관리
import { useState, useEffect } from "react";

function CourseList() {
  const [courses, setCourses] = useState([]);       // State: 시간이 지나며 바뀌는 값
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    fetch("/api/courses")
      .then((response) => response.json())
      .then((data) => {
        setCourses(data.courses);   // State를 바꾸면 React가 화면을 자동으로 다시 그림(재렌더링)
        setIsLoading(false);
      });
  }, []);

  if (isLoading) return <p>불러오는 중입니다...</p>;

  return (
    <div>
      {courses.map((course) => (
        <CourseCard key={course.id} title={course.title} price={course.price} />
      ))}
    </div>
  );
}
```

`CourseList`는 서버 데이터를 `courses`라는 **State**로 들고 있다가, `setCourses`를 호출하면 React가 알아서 화면을 다시 그립니다. `CourseCard`는 스스로 상태를 갖지 않고 부모가 준 `title`/`price` **Props**만 그대로 표시합니다.

### `useEffect`는 언제 실행되는가

`useState`, `useEffect`처럼 `use`로 시작하는 함수를 **Hook**이라고 부릅니다. `useEffect(콜백함수, 의존성배열)`은 "화면에 그려진 뒤, 의존성 배열 안의 값이 바뀔 때마다 콜백을 실행하라"는 뜻입니다.

```js
useEffect(() => { ... }, [])       // 처음 렌더링 후 딱 1번만 실행
useEffect(() => { ... }, [id])     // id가 바뀔 때마다 실행
```

Vue, Svelte는 문법이 다르지만 "부모가 자식에게 값을 내려준다(Props)"와 "컴포넌트 안에서 바뀌는 값을 관리한다(State)"는 개념은 동일합니다.

> TypeScript, SSR/SSG 같은 렌더링 방식, 성능 최적화 세부사항은 중급 가이드에서 다룹니다.

# 11. 라우팅

라우팅은 URL과 화면을 연결하는 것입니다.

```
/                 홈
/products         상품 목록
/products/10      상품 상세
```

`/products/10`의 `10`처럼 특정 항목을 식별하는 부분을 **URL Parameter**, `/products?category=book&sort=price`처럼 검색·필터·정렬을 표현하는 부분을 **Query Parameter**라고 합니다.

기본 상식: 새로고침 후에도 필요한 상태가 유지되는지 확인하고, 존재하지 않는 경로는 404 화면으로 처리하며, URL에는 민감한 정보를 넣지 않습니다.

# 12. 폼, 로딩·오류 상태, 반응형/접근성

입력 폼은 프론트엔드에서 가장 자주 만드는 기능입니다. 필수값, 이메일 형식, 길이 같은 항목을 검증합니다. **프론트 검증은 사용자 경험을 위한 것이고, 서버에서도 반드시 다시 검증해야 합니다** (7장의 "프론트 검증만으로 보안을 보장할 수 없다"는 원칙과 같은 이유).

API를 연결한 화면에서는 로딩 중 / 빈 결과 / 오류 / 인증 필요 상태를 구분해서 보여줘야 합니다. 데이터가 없다고 무조건 "오류"로 뭉뚱그려 보여주는 것이 가장 흔한 실수입니다.

**반응형 웹**은 화면 크기(모바일, 태블릿, 데스크톱)에 따라 레이아웃이 자연스럽게 바뀌는 웹입니다. **웹 접근성(Accessibility, a11y)**은 장애 여부나 사용 환경과 관계없이 누구나 웹을 쓸 수 있게 만드는 것입니다. 최소한 키보드만으로 조작이 가능한지, 이미지에 `alt`가 있는지, 입력창에 `label`이 연결되어 있는지는 확인합니다. 세부 체크리스트는 중급 가이드에서 다룹니다.

# 13. 보안 기본 상식

프론트엔드 코드와 브라우저 저장소는 사용자가 직접 열어볼 수 있습니다. 그래서 API Key나 비밀번호를 프론트 코드에 넣지 않고, 민감한 보안 판단을 프론트에서만 하지 않으며, HTTPS를 사용합니다. 빌드 시점에 넣는 환경변수도 결국 빌드 결과물에 포함될 수 있으므로 비밀값을 안전하게 저장하는 곳이 아닙니다.

사용자가 입력한 텍스트를 검증 없이 그대로 화면에 HTML로 그리면 악성 스크립트가 실행될 수 있는데, 이런 공격을 **XSS(Cross-Site Scripting)**라고 합니다. React는 `{userComment}`처럼 평범하게 값을 출력하는 한 자동으로 이스케이프해줘서 기본적으로 안전합니다. 위험 코드 예시와 인증 토큰 저장 방식 같은 세부사항은 [프론트엔드 중급 가이드](../개발%20중급%20가이드/프론트엔드%20중급%20가이드.html)를 참고하세요.

# 14. 브라우저 저장소와 디버깅

- **localStorage**: 브라우저를 꺼도 유지되는 저장 공간. **sessionStorage**: 탭을 닫으면 사라짐. **쿠키(Cookie)**: 서버 요청에 자동으로 따라붙는 작은 저장 데이터. 비밀번호는 저장하지 않고, 민감한 토큰의 저장 방식은 보안 요구사항에 따라 결정합니다.

브라우저 개발자 도구는 프론트엔드 개발의 필수 도구입니다. **Elements**(HTML/CSS 확인), **Console**(오류·로그), **Network**(API 요청/응답 확인), **Application**(저장소 확인)을 씁니다. 오류가 생기면 화면 코드만 보지 말고 재현 → Console 확인 → Network 확인 → 원인 범위 좁히기 순으로 진행합니다. 다른 사람에게 질문할 때는 "하려던 작업 / 예상 결과 / 실제 결과 / 오류 메시지 전체 / 이미 시도한 방법"을 함께 적으면 빨리 답을 받을 수 있습니다.

# 15. 빌드·배포와 Git 협업

**빌드(Build)**는 소스 코드를 브라우저가 바로 쓸 수 있는 배포용 파일로 만드는 과정이고, **배포(Deploy)**는 그 결과를 사용자가 접속할 수 있는 서버에 올리는 것입니다.

```bash
npm run build
```

을 실행하면 보통 `dist/` 폴더에 결과물이 생성됩니다. 배포 전에는 환경변수, API 주소, CORS 설정, HTTPS, Console에 남은 오류 정도는 최소한 확인합니다.

Git 협업의 일반적인 흐름입니다.

```
기준 브랜치 최신화 → 기능 브랜치 생성 → 작은 단위 구현
→ 테스트 → 커밋 → Push → Pull Request → 코드 리뷰 → Merge
```

좋은 커밋은 한 가지 목적만 담고, 메시지만 보고도 변경 내용을 알 수 있으며, 비밀값을 포함하지 않습니다.

- API Key를 프론트 코드에 작성
- AI가 생성한 코드를 이해하지 않고 그대로 사용

# 17. 직접 실습해보기 — 프론트엔드 최소 실습

목표는 예쁜 페이지가 아니라 **"프로젝트 생성 → 상태 → API → 오류 처리 → 빌드"의 전체 흐름을 한 번 경험하는 것**입니다.

## 1단계. React 프로젝트 실행

```bash
npm create vite@latest frontend-practice -- --template react
cd frontend-practice
npm install
npm run dev
```

브라우저에서 터미널에 표시된 `localhost` 주소가 열리면 개발 환경은 정상입니다.

## 2단계. 상태 하나 만들기

버튼을 누르면 숫자가 증가하는 화면을 만듭니다. `src/App.jsx`를 아래처럼 바꿔봅니다.

```jsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>클릭 횟수: {count}</p>
      <button onClick={() => setCount(count + 1)}>클릭</button>
    </div>
  );
}

export default App;
```

`count`를 `let count = 0`처럼 일반 변수로 바꾸고 값을 바꿔도 화면이 그대로인 것을 확인해보세요(리렌더링을 트리거하지 못하기 때문). React에서 화면이 바뀌는 원리는 결국 "상태가 바뀌면 다시 그린다"는 한 가지 규칙입니다.

## 3단계. 더미 데이터 목록 만들기

```js
const courses = [
  { id: 1, title: "HTML 기초" },
  { id: 2, title: "React 입문" },
];
```

`map`으로 카드 여러 개를 렌더링하고 각 항목에 안정적인 `key`를 지정합니다.

## 4단계. API 데이터로 교체하고 상태 나누기

```js
async function getCourses() {
  const response = await fetch("http://localhost:5000/courses");
  if (!response.ok) throw new Error("강의 목록 요청 실패");
  return response.json();
}
```

화면에는 로딩 중 / 성공+데이터 있음 / 성공+빈 배열 / 실패 최소 네 상태가 있어야 합니다. 개발자 도구 **Network 탭**에서 요청 하나를 클릭해 Status Code와 Response Body를 직접 확인해보세요.

## 5단계. 빌드

```bash
npm run build
```

`dist/` 같은 빌드 결과물이 생성되는지 확인합니다.

```text

State와 일반 변수의 차이는 무엇인가?

```
