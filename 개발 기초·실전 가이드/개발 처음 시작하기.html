0. 이 문서가 필요한 이유#

이 사이트의 다른 문서들은 대부분 "Git 명령어를 알고, 협업 프로젝트를 시작하는 사람"을 기준으로 시작합니다. 그런데 정말 처음이라면 그 이전에 막히는 질문들이 있습니다.

text
프로그램이 뭐지?
코드는 어디에 쓰지?
프론트엔드/백엔드가 뭐지?
Git은 왜 필요하지?
나는 지금 뭐부터 공부해야 하지?

이 문서는 그 질문들에 짧게 답하고, 각 주제를 더 깊이 배울 문서로 안내합니다. 이 문서 자체를 암기할 필요는 없습니다.

1. 프로그램이란? 프로그래밍 언어란?#

  • 프로그램: 컴퓨터에게 "무엇을 어떤 순서로 할지" 시켜놓은 명령의 묶음. 계산기, 카카오톡, 유튜브 앱 모두 프로그램입니다.
  • 프로그래밍(코딩): 그 명령을 사람이 이해할 수 있는 형태의 글로 작성하는 일.
  • 프로그래밍 언어: 그 명령을 작성할 때 쓰는 문법 체계. Python, JavaScript, Java 등은 서로 문법은 다르지만 "조건에 따라 다르게 행동한다", "같은 일을 반복한다" 같은 기본 개념은 대부분 비슷합니다.

지금 변수·조건문·반복문을 배웠다면, 이미 "프로그래밍 언어로 명령을 작성하는 것" 자체는 시작한 상태입니다. 다음 질문은 "그 코드를 어디에, 어떻게 써서 실제로 쓸 수 있는 서비스로 만드는가"입니다.

2. 코드는 어디에 작성하는가? — 에디터와 IDE#

코드도 결국 글자로 이루어진 파일(예: app.py, App.jsx)입니다. 메모장으로도 작성할 수는 있지만, 실제로는 코드 작성을 도와주는 전용 프로그램을 씁니다.

  • 에디터(Editor): 코드를 색깔로 구분해서 보여주고, 자동완성·오류 표시 같은 기능을 주는 프로그램. 대표적으로 VS Code.
  • IDE (Integrated Development Environment, 통합 개발 환경): 에디터 기능에 더해 실행·디버깅·버전 관리까지 한 프로그램 안에서 처리할 수 있게 통합한 도구. IntelliJ, PyCharm 등.
  • 요즘은 VS Code처럼 가벼운 에디터에 확장 기능을 더해 IDE처럼 쓰는 경우도 많아 두 용어의 경계가 뚜렷하지 않습니다. 지금 단계에서는 "코드를 쓰고 실행하고 오류를 확인하는 프로그램" 정도로 이해하면 충분합니다.

3. 터미널이란?#

  • 터미널(Terminal) 또는 커맨드라인(CLI): 마우스로 아이콘을 클릭하는 대신, 글자로 명령을 입력해서 컴퓨터를 조작하는 화면.
  • 예: python app.py라고 입력하면 app.py 파일을 실행하라는 명령입니다.
  • VS Code에서는 상단 메뉴 Terminal → New Terminal로 열 수 있습니다.
  • 개발에서 터미널을 쓰는 이유: 프로그램 설치, 실행, Git 명령, 서버 실행 등 대부분의 개발 작업이 결국 터미널 명령으로 이루어지기 때문입니다. GUI(마우스 클릭 화면)가 없는 도구도 많습니다.

4. 프론트엔드와 백엔드는 무엇인가?#

웹 서비스 하나는 보통 두 부분으로 나뉘어 만들어집니다.

text
사용자
 ↓ (화면을 보고 클릭·입력)
프론트엔드 (브라우저에서 보이는 부분)
 ↓ (요청을 보냄)
백엔드 (요청을 처리하는 서버)
 ↓
데이터베이스 (데이터 저장소)
  • 프론트엔드: 사용자가 눈으로 보고 손으로 조작하는 화면. HTML/CSS/JavaScript, React 같은 도구로 만듭니다.
  • 백엔드: 화면 뒤에서 요청을 받아 데이터를 검증·저장·가공하고 응답을 돌려주는 서버. Python/Flask, Node.js/Express, Java/Spring 등으로 만듭니다.
  • 하나의 서비스를 만들 때 이 둘은 반드시 "약속된 형식"으로 데이터를 주고받아야 합니다. 이 약속을 API라고 부릅니다.

더 자세한 내용: 프론트엔드 기초 가이드, 백엔드 기초 가이드 (각 문서 1장부터)

5. 서버와 데이터베이스는 무엇인가?#

  • 서버(Server): 요청을 받아서 응답을 돌려주는 프로그램. 항상 켜져 있으면서 여러 사용자의 요청을 처리합니다. (참고: "서버"는 그 역할을 하는 프로그램을 뜻하기도 하고, 그 프로그램이 실행되는 컴퓨터/장비를 뜻하기도 합니다.)
  • 클라이언트(Client): 서버에 요청을 보내는 쪽. 보통 브라우저(프론트엔드)나 모바일 앱입니다.
  • 데이터베이스(DB): 데이터를 저장해두는 별도의 프로그램/공간. 서버는 요청이 오면 필요할 때 데이터베이스에서 데이터를 읽거나 씁니다. 회원 정보, 게시글, 주문 내역 같은 것이 여기 저장됩니다.

더 자세한 내용: 백엔드 기초 가이드 5~10장 (요청-응답 흐름, 데이터베이스 기초)

6. Git과 GitHub는 왜 필요한가?#

  • Git: 코드가 바뀐 이력을 저장하고 관리해주는 도구. "이전 버전으로 되돌리기", "누가 무엇을 바꿨는지 확인하기"가 가능해집니다.
  • GitHub: Git으로 관리하는 코드를 인터넷 상의 저장소에 올려두고, 여러 사람이 함께 협업할 수 있게 해주는 서비스.
  • 왜 필요한가: 혼자 개발할 때도 실수로 코드를 망가뜨렸을 때 되돌리기 위해 필요하고, 여럿이 함께 개발할 때는 같은 파일을 동시에 수정해도 서로의 작업을 안전하게 합칠 수 있게 해주는 것이 핵심 역할입니다.

지금 바로 감을 잡고 싶다면: Git·GitHub 진짜 최소 기초

7. 지금 무엇부터 공부해야 하는가?#

이미 변수·조건문·반복문·함수 정도를 알고 있다면, 추천 순서는 다음과 같습니다.

text
1. Git·GitHub 진짜 최소 기초
   (branch·commit·push·PR·merge가 뭔지 감 잡기)

2. 관심 있는 분야 하나를 고르기
   → 화면을 만들고 싶다: 프론트엔드 기초 가이드
   → 서버/데이터를 다루고 싶다: 백엔드 기초 가이드

3. 팀 프로젝트를 시작하게 됐다면
   → 팀 개발 시작 가이드 (요구사항부터 배포까지 전체 순서)

아직 변수·조건문·반복문·함수 자체가 낯설다면, Git보다 먼저 사용 중인 언어(Python, JavaScript 등)의 기본 문법 학습을 마치는 것이 순서상 더 자연스럽습니다. 이 사이트는 그 이후 단계, 즉 "문법을 아는 사람이 실제 서비스 개발 흐름을 배우는 것"에 초점을 맞추고 있습니다.

8. 여기까지 이해했다면#

다음 질문에 자기 말로 짧게 답할 수 있으면 이 문서의 목적은 끝난 것입니다. 정답을 외우는 것이 아니라 "어느 문서로 가야 더 배울 수 있는지" 아는 것이 목표입니다.

  • 프로그램과 프로그래밍 언어는 어떻게 다른가?
  • 에디터/IDE와 터미널은 각각 어디에 쓰는가?
  • 프론트엔드와 백엔드는 화면과 서버 중 각각 어느 쪽인가?
  • 서버와 데이터베이스는 어떤 관계인가?
  • Git과 GitHub는 왜 둘 다 필요한가?
  • 나는 지금 이 사이트의 어느 문서로 가야 하는가?
