> **대상:** GitHub 계정은 있고, 프로필 페이지(`github.com/내아이디`)를 조금 더 보기 좋게 꾸미고 싶은 사람
> **목적:** 기술 스택 배지, 통계 카드, 기여 잔디를 프로필에 붙이는 방법을 감 잡기
> **주의:** 이 문서는 "재미로 해보는 꾸미기"입니다. 코드 실력이나 채용 평가와 직결되는 필수 학습 내용은 아니니, 다른 가이드 학습이 더 급하다면 나중에 봐도 됩니다.

---

# 1. 프로필 README란 무엇인가

GitHub는 **자신의 아이디와 똑같은 이름의 저장소**를 만들면, 그 저장소의 `README.md` 내용을 프로필 페이지 맨 위에 자동으로 보여주는 기능을 제공합니다.

```
github.com/mirikim79 라는 프로필을 꾸미고 싶다면
→ mirikim79/mirikim79 라는 이름의 저장소를 새로 만들고
→ 그 안의 README.md에 원하는 내용을 적으면 끝
```

* 저장소 이름이 **정확히 내 GitHub 아이디와 같아야** 이 기능이 작동합니다.
* 이 저장소는 Public(공개)이어야 프로필에 노출됩니다.
* 새 저장소를 만들 때 "Add a README file"을 체크하면 바로 시작할 수 있습니다.

---

# 2. 기본 구성 요소

프로필 README에 흔히 들어가는 요소들입니다. 전부 필수는 아니고, 마음에 드는 것만 골라 써도 충분합니다.

* **자기소개**: 관심 분야, 지금 배우고 있는 것, 연락 방법(선택) 한두 문단.
* **기술 스택 배지**: [shields.io](https://shields.io)에서 만드는 작은 이미지 배지. 마크다운 이미지 문법으로 붙입니다.
* **GitHub 통계 카드**: 커밋 수, 자주 쓰는 언어 등을 이미지로 보여주는 서드파티 서비스(대표적으로 `github-readme-stats`).
* **기여 잔디(Contribution graph)**: 프로필 자체에 이미 표시되는 잔디 외에, README 안에 별도로 넣고 싶다면 서드파티 서비스를 이용합니다.
* **방문자 카운터**: 프로필에 몇 번 방문했는지 보여주는 뱃지형 카운터.

---

# 3. 최소 예시

```markdown
### 안녕하세요, 저는 OOO입니다 👋

프론트엔드를 공부하고 있고, 최근에는 React와 TypeScript에 관심이 많습니다.

**기술 스택**

![JavaScript](https://img.shields.io/badge/JavaScript-F7DF1E?style=flat-square&logo=javascript&logoColor=black)
![React](https://img.shields.io/badge/React-61DAFB?style=flat-square&logo=react&logoColor=black)
![TypeScript](https://img.shields.io/badge/TypeScript-3178C6?style=flat-square&logo=typescript&logoColor=white)

**연락**

- 블로그: https://example.com
- 이메일: 공개하고 싶은 경우에만
```

shields.io 배지는 `https://img.shields.io/badge/<라벨>-<색상>?style=<스타일>&logo=<아이콘이름>` 형태의 URL을 만들어주고, 그 URL을 마크다운 이미지 문법으로 감싸면 됩니다(위 3장 예시 참고). 라벨·색상·로고는 [shields.io](https://shields.io) 사이트에서 직접 골라 URL을 만들 수 있습니다.

# 4. 통계 카드·잔디 넣기 (서드파티 서비스)

`github-readme-stats`, `github-readme-streak-stats` 같은 오픈소스 프로젝트는 내 GitHub 아이디를 넣은 이미지 URL을 만들어주고, 그 URL을 프로필 README에 붙이면 자동으로 통계 이미지가 렌더링됩니다.

```markdown
![내 GitHub 통계](https://github-readme-stats.vercel.app/api?username=내아이디&show_icons=true)
```

**알아두면 좋은 점**

* 이런 서비스는 대부분 **개인이 운영하는 무료 공개 서버**입니다. 공식 GitHub 기능이 아니므로 트래픽이 몰리면 일시적으로 이미지가 안 뜨거나 느릴 수 있습니다. 안 보인다고 내 설정이 잘못된 게 아닐 수 있으니, 시간을 두고 새로고침해보세요.
* 자기 서버에 직접 배포해서 쓰는 방법도 있지만(레포를 fork해서 Vercel 등에 배포), 처음에는 공개 인스턴스를 그대로 쓰는 것으로 충분합니다.
* 이런 서비스는 프로젝트마다 유지 상태가 다르므로, 사용 전에 저장소가 최근까지 관리되고 있는지 정도는 확인하는 게 좋습니다.

# 5. 자주 하는 실수

* **배지·카드를 너무 많이 붙여서 정작 자기소개 글이 안 보임.** 3~5개 정도의 핵심 배지면 충분합니다.
* **이메일·전화번호 같은 개인정보를 그대로 노출.** 공개하고 싶은 정보만 신중하게 넣습니다.
* **저장소 이름 오타.** `내아이디/내아이디`가 정확히 일치해야 프로필에 표시됩니다. 대소문자는 GitHub 아이디 자체가 대소문자를 구분하지 않으므로 문제되지 않지만, 저장소 이름을 아이디와 다르게 지으면 그냥 평범한 저장소가 됩니다.
* **화려하게 만드는 데 시간을 너무 많이 씀.** 이건 재미로 하는 꾸미기입니다 — 실제 학습·프로젝트에 쓸 시간을 이걸로 크게 줄이지는 마세요.

---

# 6. 여기까지 이해했다면

- 프로필 README가 어떤 저장소의 README.md로 만들어지는지 설명할 수 있다.
- shields.io 배지를 마크다운에 붙이는 방법을 안다.
- 통계 카드가 공식 GitHub 기능이 아니라 서드파티 서비스라는 것을 안다.
- 배지를 과하게 넣으면 오히려 안 좋다는 것을 안다.

더 배우고 싶다면: **Git·GitHub 기초 가이드**에서 저장소·커밋·PR 흐름부터 제대로 잡아보세요. 프로필 꾸미기는 어디까지나 곁가지입니다.
